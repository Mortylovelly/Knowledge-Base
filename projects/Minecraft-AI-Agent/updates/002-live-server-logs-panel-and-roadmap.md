## Контекст

Предыдущая завершённая версия — 0.3.0, commit 81661de61fbca65c8a547dac29638777c20808ed, Actions run 42653733608 (success). В 0.3.0 уже были серверный сетевой bridge, выполнение игровых инструментов на сервере, базовые NPC/mob navigation, архив чата и быстрые локальные действия без API key.

Владелец попросил временно отложить расширение инструментов и сначала сделать отдельную панель логов внутри главного меню. Требования: отдельная кнопка Logs; небольшое плавающее окно; drag, resize, collapse, крестик и повторное нажатие Logs для закрытия; три вкладки Logs / Custom logs / Errors; живые серверные логи; зелёные обычные сообщения, жёлтые предупреждения, красные ошибки; ограниченный большой буфер; прокрутка; три счётчика с момента подключения к миру и настоящие маленькие иконки Minecraft — изумруд, светокаменная пыль, редстоун.

## Изучение seasonaldaycycle

Проверен Mortylovelly/seasonaldaycycle, ветка main, commit 81ea83e64c3b7b2b32546085f6e6e17c244f6ba6. В нём нет готового плавающего перемещаемого/масштабируемого окна. ClientEventHandler, ClientSetup и MixinMinecraft содержат client tick/render hooks и сброс интерполятора при входе/выходе, но не draggable window GUI. Поэтому окно сделано под Fabric 1.20.1 архитектуру AiChatScreen; Forge UI из этого проекта не переносился.

## Реализовано в 0.3.1

### Серверный поток логов

- Добавлен серверный Log4j Core appender, подключающийся к root logger после запуска сервера и снимающийся при остановке.
- События идут в ограниченную очередь до 4096 записей. Одна пачка содержит до 18 событий; за тик может отправляться до трёх пачек. При переполнении очереди отбрасываются старейшие записи.
- Логи отправляются только подписанным клиентам. Подписка включается автоматически при JOIN; сервер проверяет OP level 2.
- Сетевые каналы: log_subscribe, log_batch, log_status.
- Custom logs распознаёт namespace com.mortylovelly и маркеры собственных проектов, включая [Fix], [Fauna], [MinecartPlus], [SkyLimitless], [Unique-Relics], [SeasonalDayCycle], [VitalCraft], [WeatherPlus].
- Errors показывает ERROR/FATAL из общего и custom потоков; WARN остаются жёлтыми в Logs/Custom logs.
- Перед передачей клиенту маскируются распространённые форматы API keys и токенов.

Важное уточнение: окно получает live events от Log4j root logger сервера, а не читает удалённую файловую систему сервера. На dedicated server это события серверного процесса; в singleplayer root logger интегрированного сервера и клиента общий. Перед подключением клиента старые события не воспроизводятся.

### Клиентский буфер и счётчики

- Добавлен AiLogClient с in-memory ring buffer до 5000 событий.
- Буфер и счётчики сбрасываются на JOIN/DISCONNECT.
- Счётчики считают физические строки, включая многострочные stack traces.
- Три счётчика показываются независимо от выбранной вкладки.
- Локальные записи AiAgentLog также попадают в Custom logs.
- Live buffer не сохраняет весь серверный лог на диск.

### Плавающее окно

- Добавлен AiLogOverlay поверх AiChatScreen; второй Screen не создаётся.
- Logs в главной панели открывает и закрывает окно.
- Перемещение — drag по заголовку; resize — нижний правый угол.
- Сворачивание/разворачивание — кнопка −/+; закрытие — × или Logs.
- Внизу расположены Logs / Custom logs / Errors.
- Под списком и над вкладками расположены три мини-показателя с Items.EMERALD, Items.GLOWSTONE_DUST и Items.REDSTONE.
- Текст автоматически переносится при изменении ширины; область логов ограничена scissor region; прокрутка ограничена буфером.
- Положение и размеры ограничиваются границами экрана и корректируются после resize.
- AiAgentLog зеркалирует локальные диагностические сообщения в custom log buffer.

## Сохранённый roadmap — будущие возможности по запросу владельца

Следующие задачи НЕ входят в 0.3.1 и не должны называться реализованными.

### 1. Полная система игрового чата
- Читать максимально доступную историю обычного чата, системных сообщений и сообщений сервера.
- Искать по нику, словам, координатам, времени и типу сообщения.
- Надёжно распознавать координаты из разных форматов и связывать их с автором/контекстом.
- Находить старые координаты и выполнять телепортацию по запросу.
- Общаться через @AI из обычного чата и через панель.
- Расширить структурированную память, сохраняя только полезную информацию.
Текущий AiGameChatHistory хранит до 1800 сообщений, которые клиент получил во время подключения; он не восстановит сообщения до установки мода, во время offline или не доставленные клиенту.

### 2. Сообщения с разными именами
- Пользовательские видимые подписи: AI, Server, NPC и произвольные имена.
- Уже есть серверное системное сообщение с настраиваемой подписью.
- Нельзя выдавать unsigned system message за настоящее подписанное сообщение другого игрока или обходить аутентификацию аккаунта. Это различие сохранять в дальнейшем.

### 3. Полноценное вселение в мобов
- Сейчас есть поиск/создание сущностей и server navigation: follow, move_to, stop, attack_entity.
- Нужно полноценное possession: переключение камеры на выбранную сущность, управление движением и действиями, выход и возврат.
- Отдельные адаптеры для наземных, летающих, водных, ездовых и модовых существ.
- Навигация моба не равна полному управлению им как игроком.

### 4. NPC с внешностью игрока
- NPC без отдельного аккаунта/входа на сервер.
- Скин выбранного игрока, ник, модель/внешность, маршрут, поведение, следование и поручения.
- Текущие NPC — server-side mob/entity с custom name; копирование скина и полноценная fake-player сущность пока не реализованы.
- Не путать визуальную копию игрока с отдельным аутентифицированным аккаунтом.

### 5. Инструменты и тестирование других модов
- Расширить инструменты на crafting, recipes, containers, equipment, attributes, combat, pathfinding, взаимодействия, предметы/блоки/сущности других модов, структуры/биомы/измерения.
- Отдельный repeatable test runner: подготовка сценария, последовательные действия, проверка ожидаемого состояния, отчёт.
- Повторяемые тесты исполнять локальной логикой без отдельного AI request для каждого шага.
- Разделять факт успешного вызова инструмента, проверенное ожидаемое состояние и ручной runtime test.

### 6. Дальнейшая экономия токенов
- Сохранять локальные быстрые действия, выбор только нужных tool definitions, компактные результаты и локальный поиск чата.
- Расширить parser частых русских команд.
- Добавить summaries, кэширование с корректной инвалидацией, структурированное хранилище координат/мест/предметов.
- Добавить статистику API: requests, input/output tokens, примерная стоимость по provider, средний размер контекста.
- Не вызывать ИИ на каждое сообщение чата, тик или шаг моба.

### 7. Развитие логов
- Проверить live stream на dedicated и integrated server.
- Уточнить namespaces/markers всех собственных модов; при необходимости дать public API/config для logger prefixes.
- При необходимости добавить копирование/экспорт логов и очистку.
- Подписку при закрытии окна можно оптимизировать позже, но статистика должна сохранять события с момента входа в мир. Сейчас подписка автоматически активна после JOIN.

## Следующий шаг

1. Установить один и тот же JAR 0.3.1 в mods клиента и Fabric 1.20.1 server.
2. Проверить OP 2 и подключение.
3. Открыть Right Shift → Logs; проверить статус.
4. Проверить обычный лог, warning и контролируемую ошибку; проверить цвета, вкладки и счётчики.
5. Переместить, изменить размер, свернуть/развернуть, прокрутить, закрыть крестиком и повторно открыть через Logs.
6. Проверить сброс counters после DISCONNECT и отсутствие серверного lag.

До получения реального тестового лога runtime-совместимость не подтверждена.
