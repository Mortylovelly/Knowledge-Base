# 002 — Зафиксировано ограничение сезонных полей config

- **Дата:** 2026-11-14
- **Проект:** seasonaldaycycle / Vertex
- **Линия Minecraft / ветка:** Minecraft 1.20.1 Fabric, `minecraft-1.20.1-fabric`
- **Версия мода:** `1.1.0-mc1.20.1`
- **Статус записи:** подтверждено по текущим исходникам; код не менялся

## Исследование

В `ModConfig.Config` определены и загружаются объекты `spring`, `summer`, `autumn`, `winter` с полями `dayTicks` и `nightTicks`; метод `sanitize()` проверяет эти значения. Однако методы расчёта `getSpringDayTicks(long)`, `getSpringNightTicks(long)`, `getSummerDayTicks(long)` и остальные возвращают жёстко заданные числовые константы, умноженные на cycle scale, и не читают соответствующие поля `values.spring/summer/autumn/winter`.

## Вывод

Изменение сезонных day/night полей вручную в `config/seasonaldaycycle.json` не меняет сезонные пропорции в текущем коде. Per-world `cycleLengthTicks` из `.seasonaldaycycle.json` используется; базовые сезонные отношения остаются заданными в Java.

## Ограничения

Это статическая проверка исходников. Не проверялось, как именно выглядит конфигурационный файл после первого запуска и как GUI ведёт себя в игре. Исходный код не изменялся.

## Следующий шаг

Если владелец захочет настраиваемые сезонные пропорции, потребуется отдельная кодовая задача: подключить getters к загруженным SeasonConfig values и проверить сохранение/синхронизацию в singleplayer и dedicated server.
