# START HERE — как пользоваться базой

Эта база хранит долговременный контекст разработки Minecraft-модов Mortylovelly. Она нужна для продолжения работы в новых чатах ChatGPT и для самостоятельного чтения владельцем.

## Текущий рабочий стандарт

**Minecraft Java Edition 1.20.1 + Fabric + Java 17.** Другие игровые версии не использовать для новых изменений, пока владелец сам прямо не сообщит о переходе. Полное правило — в [VERSION_POLICY.md](VERSION_POLICY.md).

Если возвращаемся к старому проекту, а в нём несколько версий/веток и нужная не очевидна, сначала спроси владельца, какую ветку/версию продолжаем. Не угадывай и не редактируй `main` по умолчанию.

## Если ты открыл этот репозиторий впервые

1. Прочитай этот файл целиком.
2. Прочитай [VERSION_POLICY.md](VERSION_POLICY.md) и [GLOBAL_RULES.md](GLOBAL_RULES.md).
3. Прочитай [WORKFLOW.md](WORKFLOW.md) — пошаговый процесс изменения модов.
4. Открой [PROJECTS_INDEX.md](PROJECTS_INDEX.md), найди нужный мод и перейди в его папку.
5. В папке проекта сначала прочитай `PROJECT.md`, затем записи в `updates/` по возрастанию номера.
6. Перед реальными изменениями всегда проверь актуальные файлы, ветку и GitHub Actions в исходном репозитории. Эта база — память о решениях, а не замена исходному коду.
7. Если версия/ветка неоднозначна — задай один короткий вопрос и не вноси изменения до ответа.

## Обязательная инструкция для ChatGPT

При начале работы в новом чате:

- Открой репозиторий `Mortylovelly/Knowledge-Base`.
- Прочитай `START_HERE.md`, `VERSION_POLICY.md`, `GLOBAL_RULES.md`, `WORKFLOW.md`, `PROJECTS_INDEX.md`.
- Найди нужный проект и прочитай его `PROJECT.md` и историю `updates/`.
- Проверь исходный GitHub-репозиторий: ветки, HEAD-коммит, затрагиваемые файлы и workflow run.
- Считай реальный код и Actions источником фактического состояния; база — долговременная память о решениях и контексте.
- Не переключайся на версии, отличные от 1.20.1 Fabric / Java 17, без явного указания владельца.
- Если проект содержит несколько линий и какая нужна неясно, спроси владельца до любых правок.
- После существенного этапа, когда владелец просит сохранить работу, обнови базу по [LOGGING_PROTOCOL.md](LOGGING_PROTOCOL.md).

## Как устроены папки

| Путь | Что там лежит |
|---|---|
| `projects/` | Отдельная документация каждого мода |
| `projects/<мод>/PROJECT.md` | Постоянный паспорт мода: назначение, версии, архитектура, команды, сборка, совместимость, текущее состояние |
| `projects/<мод>/updates/` | История изменений с последовательными номерами: 001, 002, 003… |
| `shared/` | Общие сведения о Minecraft/Fabric и совместимости |
| `templates/` | Шаблоны для новых проектов и записей об обновлениях |
| `archive/` | Импортированные экспорты чатов и дополнительные первичные материалы |

## Правило нумерации истории

Каждая новая запись — отдельный Markdown-файл в папке `updates/`:

`001-короткое-название.md` → `002-короткое-название.md` → `003-короткое-название.md`

Номер всегда следующий свободный, никогда не переиспользуется. Старые записи не переписывать задним числом. Если в старой записи обнаружилась ошибка, создать новую запись с исправлением и ссылкой на старую.

В `PROJECT.md` поддерживать краткое текущее состояние и ссылки на важные записи. Подробности и хронологию хранить в update-файлах.

## Как сохранить результаты текущего чата

Когда владелец говорит «сохрани», «запиши в базу», «сохрани логи» или аналогичное:

1. Выбери правильный проект.
2. Добавь следующую по номеру запись в `updates/`.
3. Запиши дату, цель, исходную проблему, факты и симптомы, гипотезы отдельно от подтверждённых причин, файлы и ветки, изменения, ссылки на коммиты, результаты сборки и реальные тесты, откат/риски, оставшиеся задачи.
4. Обнови раздел «Текущее состояние» в `PROJECT.md`.
5. Обнови `PROJECTS_INDEX.md`, если поменялись версия или статус.
6. Проверь, что ссылки и номера записей верны.

Под «сохранить логи» по умолчанию понимается подробная структурированная запись содержания доступной переписки и технических действий, а не автоматическая дословная запись каждого сообщения ChatGPT. Для дословного архива нужен экспорт данных ChatGPT, который владелец загружает в `archive/chat-exports/`.

## Главное правило

**База памяти объясняет контекст; GitHub-репозиторий мода показывает фактический код.** Перед любым изменением проверять оба источника и никогда не путать документацию, предположение, успешную сборку и проверку в реальной игре.
